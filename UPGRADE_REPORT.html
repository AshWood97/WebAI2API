本次落地的升级点

借鉴 WebModel（双协议）

  • POST /v1/messages
    Anthropic Messages API，Claude Code / Anthropic SDK 可直连。 支持 system、text/image blocks、流式 SSE、thinking 块透传。
  • GET /v1/providers
    适配器 × 模型 × Worker 聚合状态视图。

借鉴 WebAI-to-API（运维契约）

  • GET /health /ready
    免鉴权存活/就绪探针；安全模式或登录模式时 ready 返回 503。
  • POST /v1/stateless/chat/completions
    客户端自持完整历史；拒绝 conversation_id。
  • GET /openapi.json
    OpenAPI 3.0 契约，覆盖全部新增端点。
  • GET /v1/runtime/status /v1/auth/status
    队列、Worker、模型、系统资源、今日统计与登录就绪状态。
上游优势保留：Camoufox 反检测、多窗口并发与账号隔离、LMArena/Gemini/ChatGPT/DeepSeek/豆包/Sora 等广适配、WebUI 管理、任务队列与故障转移。 本次只做协议层与运维层增量，不动浏览器自动化内核。

未纳入本次升级的候选项
  • Tool Calling 原生执行 — 浏览器模拟链路无法真实执行 function call；当前将 tool_use 块序列化进提示词上下文。
  • Google Generative AI 兼容端点（WebAI-to-API 的 /v1beta/models/...）— 需要额外客户端生态，优先级低于 Anthropic。
  • 会话持久化管理（/v1/conversations）— 本地 WebAI2API 文本模式已是虚拟上下文，无服务端会话可清理；Stateless 端点覆盖主要需求。
  • npx 一键启动（WebModel）— 依赖 Camoufox 浏览器资源，不适合纯 npx 分发；现有 Docker / npm start 更合适。
  • gpt4free fallback（WebAI-to-API）— 与 Camoufox 真浏览器路线定位不同，混合会增加账号风控面。
